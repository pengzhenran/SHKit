# 物理量与单位换算

> 对应代码：`shkit/units.py`（公式层）与 `shkit/filters.py`（物理常数）
> 验证脚本：`tests/validate_units.py`（45 项，全部与手算值核对）

---

## 0. 先说结论：两条公式、一个中间量

整个管道只有两条公式，中间是**经典无量纲位系数** `C_nm`（GRACE Level-2 公布的那一套）：

```
正变换（由「输入是」决定）：  输入网格 ──÷ f_u──> C_nm = a_nm / f_u
反变换一（永远如此）：        重建场 = C_nm × f_u   ← 与输入同物理量，可直接比对
反变换二（由「输出为」决定）： 输出场 = C_nm × f_t   ← 另一个物理量的场

导出的系数文件 = C_nm（永远是它）
```

**重建场与输出场是两个不同的场**，界面上分开显示、分开导出：

| | 公式 | 物理量 | 用途 |
| --- | --- | --- | --- |
| **重建场** | `C_nm × f_u` | **恒与输入相同** | 差值图、残差 RMS、往返校验——只有它才能和原始网格逐点比 |
| **输出场** | `C_nm × f_t` | 由「输出为」决定 | 交付/画图用的另一个物理量 |

选「输出为 = 不换算」时 `f_t = f_u`，两个场是同一个（软件只算一次）。

`a_nm` 是该网格**自身**的球谐系数（只由数据与积分元决定）。`f_u` 由「输入是」
选的物理量决定：

| 输入是（`field_unit=`） | 正变换公式 `f_u` |
| --- | --- |
| `geopotential` | 1（网格本身就是无量纲位系数场） |
| `geoid` | `R = 6378136.46 m`（**常数**） |
| `surface_density` | `R·ρ̄/3 · (2n+1)/(1+k′ₙ)` |
| `ewh` | `Aₙ = R·ρ̄/(3ρ_w) · (2n+1)/(1+k′ₙ)` |
| `radial_displacement` | `R·h′ₙ/(1+k′ₙ)`（注意 `h′₀ = 0`，0 阶不可反推） |
| `scalar` / `unknown` | 1（没有物理公式，导出的就是该场自身的系数） |

**所以换「输入是」会改变导出的系数。** 实测（`sample_data/grid_global_2deg.nc`，
`rule='grid'`，nmax=12，统一导出位系数）：

```
输入 = 重力位系数   → C[2,1] = +1.814598075355e-01
输入 = geoid       → C[2,1] = +2.845028617269e-08     比值 1.567856e-07 = 1/R
输入 = EWH         → C[2,1] = +2.149903997383e-09     比值 1.184782e-08 = 1/A₂
输入 = 面密度 σ     → C[2,1] = +2.149903997383e-12     比值 = 1/(A₂·ρ_w)
```

同一块网格声明成 geoid 与声明成 EWH，是两个**不同的物理场**，所以位系数不同
（第 2 阶差 `A₂/R ≈ 13.2` 倍，而且**逐阶不同**——`Aₙ` 不是常数）。

换「输出为」则**既不改变导出的系数，也不改变重建场**（重建场恒与输入同量），
它只换**输出场**：

```
输入 = EWH，输出 = EWH   → 输出场 = 重建场（f_t = f_u）
输入 = EWH，输出 = geoid → 输出场 = C_nm × R
输入 = EWH，输出 = σ     → 输出场 = EWH 输出场 × ρ_w   （实测比值 1000.000000）
```

一句话：**「输入是」决定导出什么系数与重建场是什么量，「输出为」决定输出场是什么量。**

### 往返精确，但往返**不能**验证物理含义

**重建场**取的就是 `f_t = f_u`，正反互相抵消，`C_nm × f_u` 逐位还原成 `a_nm`
（实测 3.05e-16），所以**「网格 → 系数 → 网格」的往返精度与选哪一档声明无关**——
它恒等于机器精度。`tests/validate_units.py::t_roundtrip_is_unit_agnostic` 就是核这一条。

但这只证明 `分析` 与 `综合` 互逆，**不说明系数的数值有正确的物理意义**：
任何一对自洽的算子都能完美往返，哪怕两边用的是错的常数，甚至两边乘上一个瞎编的因子，
往返照样闭合。所以要验证含义，必须拿**与球谐展开无关的独立物理量**去核对。见
`tests/validate_physics.py`：

| 检验 | 独立已知量 | 实测结果 |
| --- | --- | --- |
| 常数水层 | 总质量 `M = ρ_w·4πR²·e₀`（纯几何） | 5 cm 全球水层 → `M = 2.556e16 kg`，位系数 `C₀₀ = M/M_地球 = 4.262795202906e-09` **精确吻合** |
| 单个谐波 | 解析已知：该系数 `= 1`，其余 `= 0` | n≤24 全部精确命中，其余最大 `7.5e-15` |
| 球冠载荷 | 总质量由**面积 × 密度**独立算出 | 指定 1.0e15 kg，由系数反推 `9.997e14 kg`（残差 0.03%，来自 0.5° 网格对冠边缘的离散） |
| `Aₙ` 本身 | 用载荷位场**第一性原理重新推导** | n=2,7,15 逐阶吻合到 1e-12（不是拿 Aₙ 的定义去验 Aₙ） |
| `geoid` 因子 | 定义 `N = R·ΣC_nm Y_nm` | 恒为 `R = 6378136.46 m` |

由此得到的定性结论也有数值支撑（同一份数据、逐阶）：

```
  n      位系数→EWH (Aₙ)     位系数→geoid      geoid→EWH        两者之比
  0      1.172939e+07      6.378136e+06     1.839000e+00    6378136.4600
  2      8.440368e+07      6.378136e+06     1.323328e+01    6378136.4600
 10      2.645541e+08      6.378136e+06     4.147827e+01    6378136.4600
 20      5.066241e+08      6.378136e+06     7.943137e+01    6378136.4600
```

- 最后一列**恒等于 R**：把起点判断错（位系数当成 geoid），EWH 结果会**整体差一个 R**，
  每一阶都差同一个倍数——是比例性错误，不是某一阶"看不出差异"；
- 而 `Aₙ` 自己 0→20 阶跨 **43.2 倍**，所以位系数→EWH 是真正逐阶的。

### 那"几套系数不能混用"到底指什么？

指**不同的数字数组**之间不能混用。物理上同一个场（比如全球 5 cm 水层），
用 EWH 表示是一串数、用 geoid 表示是另一串数、用无量纲位系数又是第三串数；
这三串数各自算出各自的系数，**它们当然不同**。

而 `f_u` / `f_t` 就是把"我手里这串数是什么"翻译成"经典位系数"（以及翻译回去）的
两条公式。起点判断错就是 1e7～1e8 倍的误差，所以软件不猜——它要求你声明，
并且在声明矛盾（例如"普通标量 → EWH"）时**直接拒绝**而不是给一个错 1e7 倍的结果。

## 1. 跨物理量时的问题来源

一个网格里的数字本身没有物理含义。同一串数字可能是

- **水准面高** ΔN（米）
- **等效水高** EWH（厘米）
- **面密度** σ（kg/m²）
- **径向形变** u_r（毫米）
- 或者就是一个**无量纲场**（例如区域平均核）

当你要在它们之间换算时，各自展开成球谐后的系数是**逐阶不同的几套数**——
不能相加、不能比较、也不能用一个常数互相换算。

从无量纲重力位系数（GRACE Level-2 公布的 `C_nm, S_nm`）换到 EWH 要乘

$$A_n=\frac{R\,\bar\rho_E}{3\rho_w}\cdot\frac{2n+1}{1+k'_n}$$

**它不是常数。** 用随包的载荷勒夫数实测：

```
n=0   A_0 = 1.1729e7
n=6   A_6 = 1.6760e8     ← 仅 0→6 阶就跨了 14.3 倍，之后还按 n 继续增长
```

所以两套系数既不能相加、也不能"乘一个系数"互相转换；而**重复乘一次 Aₙ 会把结果放大 1e7~1e8 倍**。

## 2. 各种量的换算因子

以**无量纲重力位系数** `C_nm, S_nm` 为规范中间量（4π 归一化谐函数，`R = a`）：

| `field_unit` | 物理量 | 从 `C_nm` 出发的逐阶因子 | 需要的 Love 数 |
| --- | --- | --- | --- |
| `'geopotential'` | 无量纲重力位系数 | `1` | — |
| `'geoid'` | 水准面高 ΔN | **`R`（常数！）** | — |
| `'surface_density'` | 面密度 σ (kg/m²) | `R·ρ̄/3 · (2n+1)/(1+k′ₙ)` | k′ |
| `'ewh'` | 等效水高 | `R·ρ̄/(3ρ_w) · (2n+1)/(1+k′ₙ)` = `Aₙ` | k′ |
| `'radial_displacement'` | 径向形变 u_r | `R·h′ₙ/(1+k′ₙ)` | **k′ 与 h′（均已随包）** |
| `'scalar'` | 普通标量（无物理换算） | 不定义 | — |

实测因子表（`python -c "import shkit.units as u; print(u.describe_conversion(6))"`）：

```
  n               水准面             面密度             EWH
  0      6.378136e+06    1.172939e+10    1.172939e+07
  1      6.378136e+06    3.429087e+10    3.429087e+07
  2      6.378136e+06    8.440368e+10    8.440368e+07
  3      6.378136e+06    1.021035e+11    1.021035e+08
  4      6.378136e+06    1.218319e+11    1.218319e+08
  5      6.378136e+06    1.440902e+11    1.440902e+08
  6      6.378136e+06    1.675968e+11    1.675968e+08
```

注意 **geoid 那一列是常数**——水准面与无量纲位系数只差一个 R，不是逐阶的。
但 geoid → EWH 是逐阶的。

**关于面密度 σ 与 EWH**：它们**不是两种物理量**，而是同一个量的两种单位——
`σ = ρ_w · EWH`（`ρ_w = 1000 kg/m³`）。所以它们的系数只差**常数 1000**，
不是逐阶因子。真正逐阶的是「位系数 ↔ 面密度/EWH」这一段。

**关于 `scalar` 与 `geopotential`**：两者都可能是"无量纲的数"，但含义完全不同——

- `scalar`：**没有物理含义**的标量场（区域平均核、任意无量纲网格）。无换算可做。
- `geopotential`：**重力位系数 C_nm/S_nm**，GRACE Level-2 公布的那一套。有确定的物理换算。

把核函数之类的场标成 `geopotential` 再换算，会得到一个差 `Aₙ` 倍的无意义结果，
所以软件对 `scalar` 源的换算要求是**直接拒绝**而不是猜。

### 推导（供核对）

设地表载荷面密度 `σ` 的球谐系数为 `σ_nm`（4π 归一化）：

1. 该载荷产生的位谐波为 `4πGa/(2n+1)·σ_nm`（`n=0` 时退化为 `4πGa²σ_00/r`，与均匀球壳一致 ✔）；
2. 计入地球弹性响应（载荷勒夫数 `k′ₙ`）后与无量纲 Stokes 系数的定义
   `V = (GM/r)Σ(a/r)^n C_nm Y_nm` 比较，得
   `C_nm = 3(1+k′ₙ) / ((2n+1) ρ̄ a) · σ_nm`；
3. 于是 `σ_nm = ρ̄ a (2n+1)/(3(1+k′ₙ)) · C_nm`，`EWH = σ/ρ_w`；
4. 水准面 `N = Σ a·C_nm Y_nm` → 因子 `a`；
5. 径向位移 `u_r = h′ₙ·V_load/g` → `u_r,nm = a h′ₙ/(1+k′ₙ) · C_nm`。

（`u_r` 以**向外为正**；n≥2 时 h′ₙ 通常为负，所以正载荷对应下沉。）

## 3. 代码里怎么用

### 3.0 先搞清楚：哪个参数管哪条公式

| 操作 | 作用 |
| --- | --- |
| `field_unit=`（GUI 上是「输入是」） | **正变换公式**：`C_nm = a_nm / f_u`。**会改变导出的系数** |
| `target_unit=`（GUI 上是「输出为」） | **反变换公式**：`场 = C_nm × f_t`。不改变导出的系数，只改变重建场 |
| `units.convert()` | 在两个物理量之间换算（也是走 `f` 那两条公式） |
| `units.forward_factors(u)` | 取 `f_u`；`scalar`/`unknown` 时为 1 |
| `units.to_canonical(c, src)` | 正变换：把某物理量的系数换成经典位系数 `C_nm` |

实测（`tests/validate_units.py::t_output_unit`，同一份数据）：

```
输入 = 重力位系数 → C_nm 就是该场自身的系数
输入 = geoid     → C_nm 逐阶差 1/R
输入 = EWH       → C_nm 逐阶差 1/Aₙ        ← 与 geoid 声明的结果差 Aₙ/R

输出 = 不换算 → 重建 = 原网格（正反抵消）
输出 = geoid → 重建 = C_nm × R
输出 = EWH   → 重建 = C_nm × Aₙ            ← 导出系数完全不变
```

在 GUI 上沿着真实路径又核对了一遍（`tests/test_gui_units.py`，走真实窗口 →
真实工作线程 → 真实导出文件读回）：

```
【同一份数据，逐个改「输入是」】导出 C[2,1]
    无物理含义的标量场  -1.849162537627e-01
    重力位系数         -1.849162537627e-01   （f_u = 1，恒等）
    geoid             -2.899220719443e-08   （÷ R）
    面密度 σ           -2.190855366513e-12   （÷ A₂ρ_w）
    EWH               -2.190855366513e-09   （÷ A₂）
    径向形变 u_r        → **拒绝**，报 "h′₀ = 0，第 0 阶信息已丢失"（而不是 inf/NaN）

【同一份数据，改「输出为」】导出系数一个字节都不变
    输出 = EWH / geoid / 面密度 σ → C[2,1] 全是 -2.190855366513e-09
    改的只是重建场：σ 重建 = EWH 重建 × 1000.000000（= ρ_w）
```

用一句话概括分工：**「输入是」决定导出什么系数，「输出为」决定重建回什么量。**

> 为什么这样设计：两条公式分开，用户随时能从预览栏看到"这次除的是 `R` 还是
> `Aₙ`"；导出的永远是 `C_nm`，且 `field_unit` / `forward_from` / `inverse_target`
> 三个标签一起写进文件头（`tests/validate_units.py` 有存盘回归）。

### 3.1 正变换：声明输入，得到经典位系数

```python
from shkit.analysis import analysis

# GRACE Level-2 的 C_nm/S_nm 网格：f_u = 1，导出的就是它自己
coeffs, report = analysis(lat, lon, grid, 60, field_unit="geopotential")

# 一块等效水高网格：导出的是它对应的位系数（C_nm = a_nm / Aₙ）
coeffs, report = analysis(lat, lon, grid, 60, field_unit="ewh")

# 还想顺手做别的（例如区域平均核，没有物理公式）
scalar, report = analysis(lat, lon, grid, 60, field_unit="scalar")
```

命令行等价写法：

```bash
shkit analyze --points grid.nc --nmax 60 --field-unit ewh --target-unit ewh
```

### 3.2 反变换：重建场与输出场

```python
from shkit.synthesis import synthesis

u = "ewh"                        # 「输入是」
# 重建场：与输入同物理量（目标取「输入是」那一档）
recon  = synthesis(lat, lon, coeffs, target_unit=u)

# 输出场：按「输出为」取目标物理量
v_geoid= synthesis(lat, lon, coeffs, target_unit="geoid")   # 乘 R
v_sig  = synthesis(lat, lon, coeffs, target_unit="surface_density")
```

`target_unit` 是**相对 `C_nm`** 计算的换算因子。取与 `field_unit` 相同的值时，
正反两条公式互相抵消，得到的就是**重建场**（精确回到输入网格）——所以**不存在"乘两次"**。
命令行里两者分别落在 `--out-grid`（重建场）与 `--out-field`（输出场）：

```bash
shkit analyze --points data.csv --field-unit ewh --target-unit geoid \
      --out-grid recon.csv --out-field out.csv
```

### 3.3 GUI

这两个下拉在左侧参数面板的 **「物理量与公式」** 分组里，组内第一句就是两条公式：

```
正变换（输入是）：网格 → C_nm = a_nm / f_u
反变换一：        重建场 = C_nm × f_u   （恒与输入同物理量）
反变换二（输出为）：输出场 = C_nm × f_t
导出的系数文件装的永远是 C_nm。
```

- **输入是**（**普通网格** / 水准面高 geoid / 等效水高 EWH / 径向形变 u_r，默认普通网格）：
  选正变换公式（`f_u`）。**改它，导出的系数就跟着变**——同一块网格，
  geoid 与 EWH 是两个不同的物理场。
  「普通网格」= 那串数字本身就是无量纲位系数 `C_nm/S_nm`，`f_u = 1`。
- **重建场**：永远与输入同量，所以「地图」页签里的差值图与残差 RMS 始终有意义；
  「文件 → 导出重建场（与输入同量）」导出的就是它。
- **输出为**（不换算 / EWH / geoid / **普通球谐系数** / 径向形变）：
  选输出场的公式（`f_t`）。**不改导出系数、也不改重建场**，
  只决定输出场是什么物理量；「不换算」= 用输入那一档的 `f_u`，
  输出场就是重建场。
  「文件 → 导出输出场（按「输出为」）」导出的是它。
- **实时预览**（控件正下方，灰字）：把两条公式都写成具体数字，例如

  ```
  正变换（÷ f_u，n=1 档 f_u = 3.42909e+07）：网格系数 1.32588 → 导出 C[1,1] = 3.86658e-08
  重建场（× f_u = 3.42909e+07）：该点 = 1.32588（= 原网格值，与输入同物理量，可直接比对）
  输出场（× f_t = 6.37814e+06，相对输入 × 0.186001）：该点 = 0.246616
  ```

  预览在**每次分析完成后**也会刷新；换「输入是」时第一行的 `f_u` 会当场改变
  （上例换成 geoid 就变成 `6.37814e+06`）。
- 如果两个声明互相矛盾（例如输入是"普通标量"却要输出 EWH），运行时抛出明确的中文错误
  （分析失败时上一次的结果会被清空，导出按钮随之禁用，不会静默写出旧系数）。
  GUI 下拉里已不再提供「普通标量」与「地表面密度」两档，但 API/CLI 仍然支持：
  `--field-unit scalar` / `--field-unit surface_density`。

## 4. 会被自动拦截的错误

| 错误 | 后果 | 软件的处置 |
| --- | --- | --- |
| 系数已经是 EWH，又当作位系数乘 Aₙ | 放大 ~1e7–1e8 倍 | 不适用（`target_unit` 语义下自动成为恒等） |
| 输入声明为"普通标量"，却要求换算 | 结果无物理意义 | **拒绝**，并提示先声明到底是位系数/geoid/EWH |
| 未声明（`unknown`）就要求换算 | 结果不可信 | **拒绝** |
| 把 EWH 系数当位系数去求 geoid | 差 Aₙ/R 量级 | 拒绝（源单位不可换算） |
| 确实想强行换算 | — | `allow_unit_mismatch=True` 逃生舱 |

### 关于径向形变（形变场）

径向形变的因子是 `R·h′ₙ/(1+k′ₙ)`，需要**载荷勒夫数 h′ₙ**。
SHKit 随包提供了完整的 **h′ / l′ / k′** 表，所以**开箱即可用**：

```python
v_ur = synthesis(lat, lon, coeffs, target_unit="radial_displacement")   # 直接可用
```

表来自 `PREM-LLNs.dat`（Wang et al. 2012），由 `tools/build_love_numbers.py` 转换：

```
data/load_love_numbers.npz    n, h′, l′, k′  +  n=∞ 渐近值   （46342 个度）
data/love_numbers.npy         仅 k′，与旧软件 m2py 完全一致
```

两条关键的一致性验证（`tests/validate_units.py`）：

- 自带的 `k′` 与旧软件 `m2py` 的表 **逐值一致到 9.7e-17**，所以现有的 EWH 结果不受影响；
- `k′₁` 用的是 **CE → CF** 参考系改正 `k′₁ = −(h′₁ + 2l′₁)/3`，与 `pz_LLN.m`
  里那一行完全相同（原始 PREM 文件里 `k′₁ = 0`，改正后是 0.02616765）。

**换用你自己的模型**：`pz_LLN` 目录下还有 ak135 / iasp91 / PREM-hard / PREM-soft 等：

```python
from shkit.filters import load_lln
from shkit import units
z = load_lln(r"...\LLNs\ak135-LLNs.dat")
f = units.degree_factors("radial_displacement", 60,
                         love_numbers=z["k"], love_numbers_h=z["h"])
```

短表（只有 67 行、度不连续）会按 `pz_LLN.m` 的做法**线性插值**填满，
返回值里的 `interpolated` 字段会说明是否插过。

**尚未实现的**：水平形变、三维形变、重力变化 Δg、垂线偏差。它们不只是逐阶因子问题——
例如水平形变 `u_h = (l′ₙ/g) ∇_H V`，需要**球面水平梯度算子**，
它会把 (n,m) 耦合到 (n±1,m)，不能用一个逐阶因子表达。
`l′ₙ` 已经随包提供（`load_lln()["l"]`），需要时可以实现该算子。
任意逐阶因子的通用出口是 `filters.apply_degree_filter(coeffs, factors)`。

## 5. 与旧软件 `gridSHconvert` / `m2py` 的对应

旧软件用 `out_type` 一个开关同时表示"输入是什么"和"输出是什么"，容易踩坑。对应关系：

| 旧 `out_type` | 含义（按量纲分析） | SHKit 等价写法 |
| --- | --- | --- |
| `1: normal` | 不做任何换算，系数就是输入场的系数 | `--field-unit scalar`（`f_u = 1`，导出的就是该场自身的系数） |
| `2: EWH` | **把输入网格当作无量纲位系数**，分析时除以 `Aₙ` 得到 EWH 系数 | `--field-unit geopotential --target-unit ewh`（正变换 `f_u = 1`，反变换 `f_t = Aₙ`） |

两个容易忽略的点：

1. 旧软件的分析里直接 `÷Aₙ`（`A_inv = 1/A`）。因为 `Aₙ` 的单位是米，
   所以**只有当输入网格是无量纲位系数时，结果才真的是 EWH**。
   如果输入网格本身就是"等效水高（cm）"或者"水准面（m）"，`out_type=2` 会算错。
2. 在 SHKit 里这两步是分开的：**「输入是」决定除以哪个 `f_u`**（导出经典位系数），
   **「输出为」决定乘以哪个 `f_t`**（重建回目标物理量）。
   所以"输入是什么"和"输出要什么"不会互相污染，而且无论怎么选，
   导出的系数文件装的都是同一套 `C_nm`。

## 6. 一句话总结

> **两条公式，一个中间量，两个场。** 正变换（「输入是」）把输入网格换成经典无量纲
> 位系数 `C_nm = a_nm / f_u`；反变换给出**重建场** `C_nm × f_u`（恒与输入同物理量，
> 可用于差值图与残差）和**输出场** `C_nm × f_t`（「输出为」选的物理量）。
> 导出的系数永远是 `C_nm`。所以改「输入是」**会**改变导出的系数（同一块网格声明成
> geoid 与声明成 EWH 是两个不同的物理场，第 2 阶差 `A₂/R ≈ 13.2` 倍），而改「输出为」
> 只改变输出场。声明矛盾（例如"普通标量 → EWH"）直接拒绝，而不是默默给你一个
> 差 1e7 倍的结果。
