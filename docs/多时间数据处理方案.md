## 0. 一句话结论

SHKit 的**数值内核已经具备多时次能力**（`SHCoeffs.C/S` 是 `(L+1, L+1, ntime)`，
`analysis` / `synthesis` / `filters` / `units` 都按尾轴广播），
真正缺的是**时间维的"身份、批量、算子、产品"四件事**：

| 缺的东西 | 一句话 |
| --- | --- |
| **身份** | 系数不知道自己对应哪一天；`meta` 里没有时间轴 |
| **批量** | 不能把"一个目录的 203 个 `GSM-*.gfc`"一次读成 `(61,61,203)` |
| **算子** | 没有去均值 / 趋势 / 周年 / 时间滤波 / 历元差分 |
| **产品** | 没有"点序列、区域序列、趋势场、逐历元诊断表、时间轴 netCDF" |

因此本方案**不新增数值算法**（除 GRACE 专用改正外），而是把"时间"提升为
一等公民：新增 `TimeAxis`、给 `SHCoeffs` 挂 `times`、新增 `read_coeffs_series()`、
新增 `shkit/timeseries.py`、CLI 加 3 个子命令、GUI 加 3 个页签。
**全案的工作量重心在 IO 与界面，不在数学。**

### 1.2 实测：真实 GRACE 数据上跑通了什么

对 `2_unzipped/1_CSR/01RL06/01deg60/` 的 203 个真实 `GSM-*.gfc`：

```
read_coeffs(单个 gfc)       0.003 s   → nmax=60, ntime=1
读 20 个 gfc                0.05  s   → 全 203 个外推约 0.5 s
meta["has_sigmas"]          True      → 文件带 sigmaC/sigmaS (61,61)
meta["gfc_header"]          21 个键，其中：
    time_coverage_start = ': 2002-04-05T00:00:00.00'      ← 值带前导 ": "，需清洗
    time_coverage_end   = ': 2002-05-01T00:00:00.00'
    time_period_of_data = '20020405 - 20020430 (mid: 20020418)'
```

**结论：读一个历元已经正确且极快；时间信息就在手边，只是没有被接住。**

### 1.3 实测：两个必须先修的硬缺陷

**缺陷 A —— netCDF4 打不开中文路径（本机实测，会直接砸在用户自己的数据上；已修）**

```python
xr.open_dataset(r"D:\华为家庭存储\...\3_grids\CSR_GRACE_EWH_G300.nc")
# FileNotFoundError: [Errno 2] No such file or directory: 'D:\\华为家庭存储\\...'
# 同一个路径先 shutil.copyfile 到 %TEMP% 再打开 → 正常

ds.to_netcdf(r"D:\华为家庭存储\...\out.nc")
# PermissionError: [Errno 13] Permission denied: 'D:\\华为家庭存储\\...'   ← 写也失败！
```

Python 层的 `glob`/`open`/`shutil.copyfile` 全部正常，只有 netCDF4/HDF5 的 C 库失败。
用户的**整个 GRACE 数据盘就在这个目录下**，`3_grids/*.nc` 是本方案的主要输入格式之一。

⚠️ **读和写是两回事，兜底方向相反**，而 `m2py` 只解决了读：

| | 症状 | 兜底 |
| --- | --- | --- |
| **读** | `FileNotFoundError`（文件明明在） | 复制到 ASCII 临时目录再读，**要 eager `.load()`**（临时副本返回前要删） |
| **写** | **`PermissionError`**（误导性极强） | **先写到 ASCII 临时文件，再 `shutil.move` 到位** |

**✅ 已实施（A0.5）**：`shkit.io.open_nc_dataset()` / `to_netcdf_path()` / `_write_nc()`，
4 处调用点全部改掉。修复前 `tests/run_all.py` 是 **228/231**，修复后 **231/231**。

**缺陷 B —— legacy 序列格式与 SHKit 差一层"表头 + 转置"**

```
3_processed/GRACE SH read/CSR_rawSH60_total_216.dat
    首行 = 216 个历元编号（表头），其余 3782 行 × 216 列
    np.loadtxt(skiprows=1).shape == (3782, 216)
    2*NC(nmax=60) == 3782                                   ← 正好是 to_triangle().T
CSR_rawSH60_total_216_TimeInfo.dat
    (216, 4) = [历元号, 十进制年 start, 十进制年 end, 十进制年 mid]
```

**而且我把 legacy 的十进制年口径反解出来并验证过了**（这一步很关键，
因为它决定了 `TimeAxis` 的序列化能不能和用户已有的全部中间产物对上账）：

```python
# 已实测：203 个真实文件名，200 个与 legacy TimeInfo 精确吻合（≤1e-6），
#         余 3 个是跨年历元，残留 ≤4.11e-5 年（单独的已知局限）
start = ordinal(YDDD_start)              # 文件名开始，如 2002095
end   = ordinal(YDDD_end)                # 文件名结束，如 2002120
mid   = (start + end + 1) / 2            # ← 结束日按"排他"处理，即 +1 天
base  = 366 if isleap(year_of_start) else 365   # ← 闰年用 366！
dec_year = year_of_start + (mid - ordinal(year_of_start, 1, 1)) / base
```

三个反直觉点，全都会让"看着差不多"的实现错一个月：

| 反直觉点 | 若做错 | 实测后果 |
| --- | --- | --- |
| 结束日要 **+1 天**（排他） | 全部历元偏 0.5–1 天 | **203/203 全错**（≤1e-6 命中数 = 0） |
| 闰年除数用 **366** | 每个闰年约 12 个历元偏 1 天 | 命中 146/203，最大偏差 2.7e-3 年 |
| 跨年历元（`2016346-2017006`）有独立口径 | 3 个历元偏 ~2e-5 年 | 命中 200/203，最大偏差 **4.11e-5 年 ≈ 21 分钟** |

即：**正确的口径 = 200/203 精确（≤1e-6），仅 3 个跨年历元残留 ≤4.1e-5**。
这 3 个必须在 P0 单独定标（并写进已知局限），不能假装不存在。

**✅ 已实施（A0）**，三个数字全部复现：`200/203 ≤1e-6`；反例"结束日不 +1 天" → **0/203**；
反例"闰年用 365" → **146/203**。见 `tests/validate_timeaxis.py`。

**⚠️ A0 新发现的第二个日期陷阱：两处日期语法不同**

| 来源 | 语法 | 例子 |
| --- | --- | --- |
| **文件名** | `YYYYDDD`（年 + **积日**） | `2002095` = 2002 年第 95 天 = 04-05 |
| **gfc 头部** `time_period_of_data` | `YYYYMMDD`（年 + **月日**） | `20020405` = 04-05 |

把 `20020405` 当积日解释会得到第 405 天 → **直接跳到下一年**（实测偏差约 1 年）。
所以实现里只留**一个** `_epoch_from_ordinals(start_ord, end_ord, start_year)`，
两种语法各自先转 ordinal 再进去；这条签名本身就是防呆。

另外：头部的 `(mid: YYYYMMDD)` **不用于取值**（它只到天，会丢掉 legacy 实际携带的 12:00 半点）。

**⚠️ A1 又发现两类真实数据的坑（都在用户的 `01deg60` 目录里）**

1. **有 13 个文件没有扩展名**，而且它们是 **PO.DAAC `SHM` 格式**（YAML 头 + `GRCOF2 n m C S ...` 行），
   不是 ICGEM `gfc`。`read_coeffs` 现在对无扩展名文件**嗅探内容**，并把 `GRCOF2` 与 `gfc` 同等接受
   （两者前 5 列语义相同，只是一个用 YAML 头、一个用 ICGEM 键）。
   ⇒ 用户的目录实际是 **203 个 `.gfc` + 13 个 SHM = 216 个历元**，正好对上 legacy `.dat` 的 216 列。
2. **SHM 只有 `time_coverage_start/end`，没有 `time_period_of_data`**，而 coverage 的**结束日是排他的**
   （`2021-12-01 .. 2022-01-01` 表示 12 月），与 `time_period_of_data` 的**含结束日**相反。
   两种语法要用**不同的算术**：period 走 `(start+end+1)/2`，coverage 走 `(start+end)/2`。
   写错会让 13 个历元整体偏半个月。

**结论：SHKit 的三角布局与 legacy 逐值同构，只差首行表头与时间列；
时间口径也被反解出来了。这是白送的互操作与验证锚点。**

## 3. 设计原则（先定约定，再写代码）

1. **时间只以"尾部轴 + 一个描述对象"存在。**
   不另起一套 `TimeSeries` 数值类。`analysis`/`synthesis`/`filters`/`units`
   已经写对了 3D 广播，**白拿**就是最大的胜利。新代码只做"贴标签、批量、时间算子"。

2. **时间元数据随系数走。**
   `SHCoeffs.times: Optional[TimeAxis]`（默认 `None` ⇒ 完全向后兼容），
   并在 `meta["times"]` 留一个只读别名，方便旧脚本取。
   **任何双操作数运算先校验时间轴一致**：`times(A) != times(B)` 要**报错**，
   绝不静默广播（`__add__` 现在连 meta 都不传，是明确的静默风险）。

3. **对外只有两条主路径，且明确推荐哪一条**
   - **路径 ①（推荐）**：`GSM*.gfc` 序列 → 系数序列 →（时间算子）→ 场/序列。
     读 203 个文件 0.5 s，**不经过球谐分析**，零信息损失。
   - **路径 ②（次选）**：`(time,lat,lon)` 网格 → 逐历元球谐分析 → 系数序列。
     代价见 §6，1° 全球 × 216 历元 ≈ 分钟级；且结果受 `nmax` 截断影响。
   > 文档必须把这句话写进用户手册：**有 gfc 就别重做球谐分析。**

4. **权重只算一次。** `compute_weights` 与时间无关。路径 ② 的 216 个历元
   必须共享同一套 Voronoi/Delaunay/grid 权重，否则 21 倍白干。

5. **"空间滤波"与"时间滤波"在命名与文档上物理隔离。**
   现有"300 km 高斯"是**球面空间**核；多时间引入的"3 个月滑动平均"是**时间**核。
   两者正交，都"只施加一次"。`gaussian_km` 与 `time_window` 不得共用一个参数名，
   报告里要分别写明施加顺序。这是最容易产生"看起来对了但其实错"的地方。

6. **不做等间隔假设。** GRACE 月度解间隔 27–35 天，还有整月缺失与一年两解。
   凡涉及"月"的地方一律用**真实时间间隔**（`datetime64` 差值），
   禁止 `ntime` 索引当时间用。十进制年只作为**标签与输出格式**，不作内部时间。

7. **诚实诊断优先于自动决策。** 缺测、重复、可疑历元一律**报告**，
   不自动剔除、不自动插补（除非用户显式要求）。

8. **只读用户数据。** `2_unzipped/`、`3_processed/`、`3_grids/` 全程只读；
   所有产物写到新目录（默认 `SHKit/out/`）。测试不得依赖用户数据目录。

## 4. 接口草案

### 4.1 新模块 `shkit/timeaxis.py`

```python
@dataclass
class TimeAxis:
    values: np.ndarray          # datetime64[ns]，规范内部形式（缺失时用 NaT + mask）
    kind: str = "datetime"      # 'datetime' | 'decimal_year' | 'index'
    labels: list[str] | None = None      # 原样保留，如 'GSM-2_2002095-2002120_...'
    source: list[str] | None = None      # 每个历元来自哪个文件
    meta: dict = field(default_factory=dict)

    # --- 构造（都返回 TimeAxis，且都带"怎么推出来的"记录） ---------------
    @classmethod
    def from_grace_filenames(cls, paths) -> "TimeAxis"      # 解析 2002095-2002120
    @classmethod
    def from_gfc_headers(cls, paths) -> "TimeAxis"           # 权威：time_coverage_*
    @classmethod
    def from_netcdf_coord(cls, coord) -> "TimeAxis"          # datetime64 或 数值
    @classmethod
    def from_decimal_years(cls, y, *, convention="doy365") -> "TimeAxis"
    @classmethod
    def from_index(cls, n) -> "TimeAxis"

    # --- 读取 -------------------------------------------------------------
    def __len__(self) -> int
    @property
    def decimal_years(self) -> np.ndarray      # 与 legacy TimeInfo 口径一致
    @property
    def dt_days(self) -> np.ndarray            # 相邻间隔（天），首元素 NaN
    @property
    def is_regular(self, tol_days=3.0) -> bool
    @property
    def span(self) -> tuple

    # --- 查询与切片 -------------------------------------------------------
    def select(self, idx) -> "TimeAxis"
    def slice(self, t0=None, t1=None) -> tuple["TimeAxis", np.ndarray]   # 返回布尔掩码
    def nearest(self, when) -> int
    def missing(self, cadence_days=31.0, tol_days=6.0) -> list[tuple]   # 缺测区间
    def duplicates(self, tol_days=1.0) -> list[list[int]]               # 重复历元
    def resample(self, target, method="linear") -> tuple["TimeAxis", np.ndarray]

    # --- 输出 -------------------------------------------------------------
    def summary(self) -> str                    # 中文：历元数/跨度/间隔统计/缺测/重复/来源
    def to_legacy_timeinfo(self, path) -> Path  # [idx, y_start, y_end, y_mid]
    def to_netcdf_coord(self, ds, name="time")
```

**日期解析的唯一权威顺序：gfc 头 > 文件名 > 用户显式给定。三者不一致要报告。**

文件名规则（实测）：

```
GSM-2_2002095-2002120_GRAC_UTCSR_BA01_0600.gfc
      │        │         │    │     │    └ RL: 0600=RL06, 0603=GRACE-FO RL06.3
      │        │         │    │     └──── BA01=60 阶, BB01=96 阶
      │        │         │    └────────── UTCSR / UTCSR? / GFZOP / JPL
      │        │         └─────────────── GRAC=GRACE, GRFO=GRACE-FO
      │        └───────────────────────── 结束：年+积日（2022120 = 2022 年第 120 天）
      └────────────────────────────────── 开始：年+积日（2002095 = 2002 年第 95 天）
```

**验收锚点（已实测可行，见 §1.3）**：用 203 个真实文件名按 §1.3 反解出的公式
推出的 `decimal_year`，与 `CSR_rawSH60_total_216_TimeInfo.dat` 第 4 列对比

### 4.5 新模块 `shkit/timeseries.py`（时间域算子）

**全部作用在系数域**，因为时间算子是线性的、与空间基可交换 ——
"先算系数序列 → 做时间处理 → 最后合成"是唯一主路径，
避免"对每个历元重复球谐综合/分析"。

```python
# ---- 基准与异常 ----------------------------------------------------------
def remove_mean(coeffs, *, kind="mean") -> SHCoeffs        # 'mean'|'median'|'linear'
def subtract_reference(coeffs, when) -> SHCoeffs           # 指定参考历元/日期
def anomaly(coeffs, *, reference="mean") -> SHCoeffs       # = remove_mean 的别名口径

# ---- 时间拟合（核心产品）-------------------------------------------------
def fit_trend_seasonal(coeffs, *, periods=(1.0, 0.5),
                       trend="linear",                     # 'none'|'linear'|'quadratic'
                       sigma=None, robust=False) -> "FitResult"
# FitResult: .trend_coeffs  .seasonal_coeffs  .residual_coeffs
#            .amplitude(period)  .phase(period)   .sigma_*  (1σ，含解析协方差)
#            .table  (逐 (n,m) 的趋势值/振幅/相位/SNR)  .summary()

# ---- 时间滤波 / 插补 / 重采样 --------------------------------------------
def time_filter(coeffs, *, window_days, kind="gaussian"|"boxcar"|"savgol") -> SHCoeffs
def fill_gaps(coeffs, *, method="linear"|"spline", max_gap_days=None) -> SHCoeffs
def resample(coeffs, target_times, *, method="linear") -> SHCoeffs
def difference(coeffs, *, lag=1) -> SHCoeffs

# ---- 误差传播 ------------------------------------------------------------
def propagate_sigma(sigmaC, sigmaS, op) -> tuple[np.ndarray, np.ndarray]
```

**铁律**：

1. 这些函数**必须**拿到 `times`；退化到 2D 时**报错**，不猜。
2. 时间滤波用**真实时间间隔**（不规则），Gaussian 核按 `exp(-Δt²/2σ_t²)` 并归一化，
   **不是**按数组下标卷积；报告要打印实际有效窗口与首尾被削弱的时间范围。
3. 拟合是 O(ntime·p) 的小二乘（p = 截距+趋势+2×周期数 ≤ 6），
   逐 (n,m) 独立 ⇒ 可以整体向量化成一次 `lstsq`，代价可忽略。
4. 与空间高斯滤波**叠加顺序无所谓（可交换）**，但报告里要分别列出，避免用户误判"乘两次"。

## 6. 性能与内存预算

**主路径 ①（读 gfc 序列）—— 几乎免费**

```
203 个 gfc 实测 0.5 s；拼接 (61,61,203) 仅 12.9 MB
⇒ 多时间的主要成本在"产品化"，不在计算
```

**路径 ②（网格批量分析）—— 要算清楚**

求积的浮点量级：`≈ N · (L+1)²/2 · ntime`（`legendre_columns` 按阶流式，`sum_m (L−m+1) = (L+1)(L+2)/2`）

| 场景 | N | L | ntime | 浮点量级 | 预估（BLAS ~50 GFLOPS） |
| --- | --- | --- | --- | --- | --- |
| 2° 全球 × 216 | 16 200 | 60 | 216 | 6.6e12 | ~2 min |
| 1° 全球 × 216 | 65 160 | 60 | 216 | 2.7e13 | ~9 min |
| 1° 全球 × 257（用户 `3_grids`） | 65 160 | 60 | 257 | 3.2e13 | ~11 min |

⇒ **必须**：权重一次算、`epoch_chunk` 分块、进度按"历元 k/K"报、可取消。
⇒ **必须在文档里说清**：把 gfc 拿来直接读（路径 ①，0.5 s）比重新分析网格快 **三个数量级**，
且无截断误差。

**内存**

| 对象 | 大小 |
| --- | --- |
| `C/S` = `(L+1)²·ntime·8·2`，L=60/216 | 12.9 MB |
| L=96/1000 | 150 MB |
| 输入场 `(N,ntime)`，1°×257 | 134 MB |
| 逐历元 `w` 向量（N=65 160） | 0.5 MB（复用） |

`epoch_chunk` 自动取 `min(ntime, floor(budget / (N·8·k)))`，复用现有 `_memory_budget()`。
**输入场始终整体加载**（xarray 一次读入），所以输入那一份内存是硬下限；
若要有上限，需要在 `read_grid` 上开放 `chunks=` 走 dask —— **列为不做**（见 §8）。

**已知可优化点（P2 顺带做）**：`_wlsq_cg` 逐历元重建 `LinearOperator` 并重复 `A^T W A`
应用。若 `epoch_chunk` 提供 `ntime` 列，`op.matvec/rmatvec` 已经支持多列，
可以把 `cg` 换成"对 `(ncoef, ntime)` 的块 CG"（一次迭代推进所有历元），
迭代数取各历元最大者。**这是精度中性的，但会改变迭代停止点，故必须与原版做等价性对比**
（不要求逐位，要求残差同量级）。列为 P2 的**可选**项。

## 7. 验证计划

新增第 10 套 `tests/validate_multitime.py`，并入 `tests/run_all.py`。

### 7.1 等价性铁律（最重要的一组）

| 断言 | 判据 |
| --- | --- |
| 批量 N 历元 ≡ 逐历元循环 N 次（求积/WLSQ/CG） | 系数逐位 ≤1e-12 |
| `epoch_chunk=1,3,全部` 三种分块 ≡ 不分块 | 逐位 ≤1e-14 |
| 系数域趋势拟合 ≡ 网格域趋势拟合 | 机器精度（线性性） |
| `analysis_series → synthesis_grid` 每个历元往返 | 与单历元路径一致 |

### 7.2 时间轴（P0）

- 文件名解析：正常月、跨年（`2011347-2012011`）、闰年（`2004336-2004366`）、
  一年两解、`GRFO`/`0603`、`BB01` 96 阶；
- **十进制年口径定标（P0 的核心验收）**：按 §1.3 的公式与真实
  `CSR_rawSH60_total_216_TimeInfo.dat` 对表 → **200/203 ≤1e-6**；
  3 个跨年历元按已知口径定标到 ≤4.11e-5 并把残留写进已知局限。
  同时必须各有一条**反例回归**证明"不 +1 天"和"闰年用 365"会失败
  （否则这条口径将来会被"顺手简化"改坏）；
- gfc 头解析：清洗 `": "` 前缀；`time_period_of_data` 的 `mid:` 抽取；
  **头与文件名冲突时必须报告**（构造冲突样本）；
- 十进制年 ↔ datetime64 往返；`missing()` / `duplicates()` / `is_regular` 的边界。

### 7.3 时间算子（P3）

- 合成已知信号 `f(λ,φ,t) = a(λ,φ)·t + b(λ,φ)·cos(2πt) + c(λ,φ)·sin(2πt)`：
  拟合出的趋势/振幅/相位与真值误差 <1e-6；相位用 `atan2` 且跨 0/2π 处不断裂；
- 相位/振幅**零假设**：纯趋势信号应给出振幅 ≈ 0；
- 时间滤波：不规则间隔下与逐点手算卷积一致（≤1e-12）；
  Gaussian 时间核的权重和 = 1、中心不被衰减；
- 缺测：插入 NaN 历元后 `fill_gaps` / 稳健拟合不崩、且报告插补了几个；
- **空间/时间滤波不得互相污染**：`apply_gaussian(300km)` 后再 `time_filter` ≡ 反序。

### 7.4 已知坑的回归（第 2 条会以新形式复发）

现有 `validate_core.py::t_multitime` 之外，参数化覆盖所有时间轴索引：

```
S[..., :, 0]  vs  C[:, :, t]  vs  np.mean(..., axis=2)
truncate() / apply_degree_filter() / units.convert() / to_triangle() / from_triangle()
degree_rms() / power() 的 3D 分支
```
每一项都断言"第一时次与最后时次都没有被误清零/误平均"。

### 7.5 与用户真实数据的对表（只读、可选）

| 对比 | 判据 |
| --- | --- |
| 203 个 gfc → 序列 vs `CSR_rawSH60_total_216.dat` | 重叠历元**相对 ≤1e-6**（实测 4.99e-07 = 该文本 7 位有效数字的精度极限；原写"逐值 ≤1e-15"不成立。本工作区 216 列**全部 816 912 个数字都是 7 位**；用户侧另一份约 **9 位**，≤1e-6 同样成立） |
| 文件名时间 vs `..._TimeInfo.dat` | **200/203 ≤1e-6**；3 个跨年历元 ≤4.11e-5（已定标，记入局限） |
| 本方案合成场 vs `3_grids/CSR_GRACE_EWH_G300.nc` | 同口径下逐点 RMS 差异有明确解释（滤波/去均值/GIA 差异）；**不给"必须一致"的伪判据** |

## 8. 明确不做（诚实清单，与 `方案调研.md` §9 同风格）

1. **不做 dask / 延迟加载**：输入场整体进内存，超出预算时的答案是"降分辨率或分历元区间跑"，
   不是引入第二套 IO 栈。
2. **不做完整统计推断**：只给趋势/振幅/相位的 1σ 与 SNR，
   不做 AR(1) 噪声模型、不做 Mann-Kendall、不做显著性检验的完整理论。
3. **不自动剔除/插补可疑历元**：只报告（`outliers()` 返回索引 + 中文说明）。
4. **不实现 DDK 滤波**（需要外部滤波矩阵 `.mat`，量纲/版本难验证）；
   P5 只做 `P4M6` / `P3M13` 这类可自证的去相关。
5. **不做 mascon、Slepian 时变反演、空间约束反演**。
6. **不引入 FFT 快速路径**（理由见 `方案调研.md` §5）。
7. **不做地震/洪水/干旱事件检测**（那是应用层，不是球谐工具的事）。
8. **不保证与 MATLAB 中间产物逐位相同**（版本/滤波器口径不同），
   只保证**能读能写能对上账**，差异必须可解释。
